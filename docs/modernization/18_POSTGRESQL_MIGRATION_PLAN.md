### SQLite → PostgreSQL friction points

| SQLite | PostgreSQL action |
|--------|-------------------|
| `TEXT` datetime strings | `TIMESTAMPTZ` or `TIMESTAMP` + app UTC discipline |
| `INTEGER` booleans | `BOOLEAN` |
| `AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` or UUID/text ids (keep text ids) |
| Single-writer | Connection pool (pg + `@neondatabase/serverless` N/A on Cloud SQL — use `pg` pool) |
| `datetime('now')` | `NOW()` |
| FK enforcement | Enable; audit orphan rows in staging import |

## 4. Cutover & rollback (staging rehearsal template)

### Cutover (maintenance window)

1. Enable read-only mode on API (feature flag returns 503 on mutating routes).
2. Final Litestream restore point / SQLite file snapshot to GCS.
3. Run `migrate-sqlite-to-pg.mjs --verify`.
4. Point Cloud Run `DATABASE_URL` to Cloud SQL (via Secret Manager).
5. Scale API max instances > 1 if desired.
6. Run `scripts/staging-validate.mjs` + Playwright smoke.
7. Disable read-only.

### Rollback

1. Revert Cloud Run env to `DATABASE_PATH` + Litestream image tag.
2. Restore SQLite from pre-cutover GCS snapshot if needed.
3. Document incident; do not delete PG instance until post-mortem.
